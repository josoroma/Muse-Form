# Working on MUSE + FORM

The active product consists of MUSE (`expressions/`) and FORM (`three/`). Both use the same licensed skinned adult character, shared rendering modules, local Three.js engine and five-second deterministic movement. The root page launches these two viewers.

- Keep the current character identity, camera behavior, anatomical selection, surface overlays, labels and responsive controls coherent across both apps. Inspect actual output before changing geometry or materials.
- Preserve every existing `archive/` edition. Earlier SVG, raster, procedural and skill experiments are historical material, not active product dependencies. The final accepted SVG gallery lives in `archive/svg-final/`; do not restore live corpus/skills/export duplicates.
- Current authoring skills live in `.agents/skills/`: `muse-expression`, `form-motion` and `muse-form-lab`. These are lightweight instructions and references, separate from the retired asset-heavy skill. Maintain their source maps when extension hooks change; do not copy models or engine files into them. New experiments may use `experiments/<slug>/` without replacing accepted product views or historical archives.
- `README.md` is a hand-authored product document. `README-STUDY.md` is the evidence-based development narrative. `README-STUDY-MUSE.md` covers body movement and `README-STUDY-FORM.md` covers facial expressions, following the user's requested filenames; do not swap them to match the app names. Keep these hand-authored documents intact. Viewer-specific READMEs and manifests are generated by `scripts/catalog-three.mjs` and `scripts/catalog-expressions.mjs`.
- Keep `docs/brand/` for the original logo, `docs/product/` for actual current viewer screenshots, and `docs/study/` for historical collages. Collage provenance must name the commit, original file and crop. Never label a concept image as a working render or invent traction, affiliation or test results.
- Current runtime modules are under `three/character/`, `three/runtime/` and `expressions/`. `three/geometry.mjs` retains only the active action envelope. Retired primitive builders are in `archive/procedural-v3/`.
- Preserve local asset permission evidence, CC0 inputs and the expression builder. Do not import upstream GPL generator/runtime code into this application. The source character is illustrative, not a clinical simulation or exact celebrity likeness.
- Use one absolute time to derive bone poses and morph weights. Check finite evaluated skin vertices and normals, exact 0/5-second endpoints, reverse seeking, private normal buffers and surface-following anchors. Manual orbit interrupts guided camera control.
- Review all relevant front, profile and three-quarter poses, actual playback, mobile layout and selected regions. Facial work also requires actual enlarged browser views with a face at least 450 pixels high; thumbnails concealed prior complexion, dental and morph-normal defects.
- Keep browser automation independent of the old skill: `scripts/browser.mjs` launches the installed Chrome/Chromium. Run affected `check:three`, `check:expressions`, `playback:three` and `playback:expressions` commands. Avoid rerunning geometry suites for docs-only changes; run link/import/navigation checks instead.
- Historical QA metadata is preserved in `archive/qa-records-before-cleanup/`. Current `qa/` holds retained final evidence and reproducible check output. Do not relabel old screenshots or hashes as fresh validation. Document review scope and limits accurately.
- Regenerate viewer catalogs after their source metadata changes. `npm run bundle:three` generates a current-product ZIP under ignored `dist/`; it must not duplicate the historical archive or retired skill. No video export is requested.
